# ADR-0001 技术栈决策

## 1. 基本信息
- ADR 编号：0001
- 标题：V1 后端技术栈与整体架构决策
- 状态：Accepted
- 决策日期：2026-03-09
- 决策人：项目发起人 + 技术负责人
- 最近更新：2026-03-09（后端框架由 Laravel 调整为 ThinkPHP）

## 2. 背景
平台需在 12 周内完成 V1 主流程交付，核心诉求包括：

- 需求池状态机 + 评审事件落地
- 执行与日常执行双轨协同
- 执行作为独立菜单集中管理在研阶段，项目菜单保留列表总览
- 团队甘特冲突检测
- 自动日报/周报生成
- 页面/按钮级权限与审计
- 站内通知 + 钉钉消息 + 钉钉账号绑定

团队明确平台仅内部使用，采用单组织单租户，不考虑首期多租户复杂度。

## 3. 备选方案

### 3.1 后端方案
- 方案A：NestJS（TypeScript）
- 方案B：Spring Boot（Java）
- 方案C：PHP（ThinkPHP）

### 3.2 前端方案
- 方案A：React + Vite
- 方案B：Next.js

### 3.3 组织模型方案
- 方案A：单组织单租户
- 方案B：多组织多租户

## 4. 决策结果

### 4.1 最终选择
- 后端：PHP 8.3 + ThinkPHP 8
- 前端：React + Vite
- 权限粒度：V1 页面级 + 按钮级
- 菜单结构：项目与执行分离（项目列表总览 + 执行独立入口）
- 甘特拖拽改期：不进入 V1
- 工时管理：纳入 V1（轻量工时日志 + 每日工作内容，复杂核算不进入 V1）
- 通知：站内 + 钉钉
- 账号：账号密码登录，并支持钉钉绑定
- 组织模式：单组织单租户（仅内部团队）

### 4.2 选择理由
- PHP/ThinkPHP 方案适合快速搭建稳定的管理后台与 CRUD 主流程
- ThinkPHP 结构轻、上手快，适合内部平台快速迭代
- React + Vite 前端开发效率高，管理台生态成熟
- 页面/按钮级权限能在工期内达成“可控 + 可审计”
- 轻量工时日志纳入 V1，有利于日报与管理员统计闭环
- 单组织单租户明显降低数据隔离和权限复杂度

## 5. 影响评估

### 5.1 正向影响
- 交付节奏可控，风险更低
- 技术方案与业务需求贴合，开发路径清晰
- 可在 V2 增量扩展复杂能力，不阻塞 V1 上线

### 5.2 负向影响
- 后端与前端语言不统一（PHP + TS），需增强接口契约与联调规范
- 暂不支持字段级权限，部分高精细授权场景需要人工规避
- 暂不支持甘特拖拽，排期操作效率略低

## 6. 实施约束
- 所有接口必须有后端权限校验，前端显示权限不作为安全边界
- 批量写操作必须支持幂等键
- 审计日志必须覆盖需求评审、状态流转、执行分配、排期修改、缺陷提交
- 钉钉推送必须异步化，失败可重试并可告警

## 7. 回滚与替代策略
- 若 ThinkPHP 无法满足并发或扩展性，可通过以下路径演进：
  1. 保持 API 契约不变，拆分高负载模块为独立服务
  2. 使用消息队列解耦报告生成与通知流程
  3. 在 V2/V3 评估迁移至服务化架构
